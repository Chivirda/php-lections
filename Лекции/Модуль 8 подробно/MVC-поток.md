
## 🔷 0:08–0:18 — **MVC-поток в веб-приложении**

**Цель:** Понять, как работает архитектура MVC в современных PHP-фреймворках (например, Laravel) и какая у неё последовательность обработки запроса.

---

### 🔹 MVC — что это?

**Model — View — Controller** — архитектурный шаблон, разделяющий логику приложения на 3 части:

|Компонент|Ответственность|
|---|---|
|**Model**|Бизнес-логика, работа с данными и БД|
|**View**|Представление — что отображать пользователю|
|**Controller**|Принимает запрос, вызывает Model и View|

---

### 🔸 Поток обработки HTTP-запроса

Разберём по шагам типичный процесс запроса в Laravel (или любом MVC-фреймворке):

---

### 1. **Front Controller**

Это **единая точка входа** в приложение.  
В Laravel — это файл `public/index.php`.

```php
require __DIR__.'/../vendor/autoload.php';
$app = require_once __DIR__.'/../bootstrap/app.php';
$app->run();
```

- Грубо говоря: любой HTTP-запрос идёт в `index.php`.
- Это позволяет централизованно обрабатывать всё: маршрутизацию, middleware, ошибки и т.д.

---

### 2. **Router**

Следующий этап — маршрутизатор.

```php
Route::get('/profile', [ProfileController::class, 'show']);
```

- Определяет: **какой контроллер** и **какой метод** вызвать.
- Использует паттерн URI → обработчик.

---

### 3. **Controller**

Контроллер получает запрос и обрабатывает его.

```php
class ProfileController extends Controller {
    public function show(Request $request) {
        $user = User::find($request->user()->id);
        return view('profile', ['user' => $user]);
    }
}
```

- Может запрашивать модель, сервис, логгер и др.
- **Не содержит бизнес-логики** — только координирует.

---

### 4. **Model**

Работает с базой данных, инкапсулирует бизнес-логику:

```php
$user = User::find(1);
```

- В Laravel это `Eloquent ORM`, но может быть любая логика (репозитории, сервисы).

---

### 5. **View**

Возвращает HTML-ответ:

```blade
<!-- resources/views/profile.blade.php -->
<h1>Hello, {{ $user->name }}</h1>
```

- Представление не должно содержать логики, кроме базовой (циклы, условия).
- В Laravel чаще используется Blade, но может быть Twig, Smarty и т.д.

---

### 6. **Response**

Laravel автоматически оборачивает результат в HTTP-ответ и отправляет его браузеру.

---

### 📊 Интерактив: диаграмма на доске

Нарисуйте следующую схему потока:

```
[Браузер]
    ↓
index.php (Front Controller)
    ↓
Router (по URI)
    ↓
Controller
 ↙         ↘
Model      View
    ↘     ↙
   Response → [Браузер]
```

---

### 💡 Почему это важно?

- MVC делает код **модульным**, **тестируемым**, **поддерживаемым**.
- Позволяет **перераспределить обязанности** между разработчиками (бек, фронт, логика).
- Помогает масштабировать проект.
