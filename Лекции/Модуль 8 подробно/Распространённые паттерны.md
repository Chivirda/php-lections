### 🔹 Что такое шаблоны проектирования?

**Шаблон проектирования (Design Pattern)** — это **универсальное решение часто встречающейся проблемы** в проектировании программ.

- Не готовый код, а **структура**  
- Не «магия», а **доказанный временем способ решения**  
- Помогают писать код **гибко, расширяемо, читаемо**

### 🏭 1. **Factory Method (Фабричный метод)**

**Проблема:**  
Клиент не должен зависеть от конкретного способа создания объектов.

**Пример:**

```php
interface Transport {
    public function deliver();
}

class Truck implements Transport {
    public function deliver() { echo "По земле 🚚"; }
}

class Ship implements Transport {
    public function deliver() { echo "По морю 🚢"; }
}

class TransportFactory {
    public static function create($type): Transport {
        return match ($type) {
            'truck' => new Truck(),
            'ship' => new Ship(),
        };
    }
}
```

**Laravel-пример:**  
Контейнер `app()->make(FooService::class)` — по сути **фабрика**, которая знает, как собрать объект.

---

### ⚠️ 2. **Singleton (Одиночка)**

**Суть:**  
Класс, у которого может быть только **один экземпляр**.

```php
class AppConfig {
    private static $instance;

    private function __construct() { }

    public static function getInstance(): AppConfig {
        if (!self::$instance) {
            self::$instance = new self();
        }
        return self::$instance;
    }
}
```

---

**Почему это антипаттерн (вреден):**

- Глобальное состояние → сложно тестировать  
- Неявные зависимости  
- Плохо работает с DI  

**Когда можно использовать:**  
Для неизменяемых конфигураций или кеша, но лучше через **контейнер**.

---

### 📁 3. **Repository (Репозиторий)**

**Зачем:**  
Изолировать бизнес-логику от конкретной ORM или БД.

```php
interface UserRepository {
    public function findById($id);
}

class EloquentUserRepository implements UserRepository {
    public function findById($id) {
        return User::find($id);
    }
}
```

**Laravel:**  
Хотя Eloquent сам похож на репозиторий, большие проекты используют **явные репозитории**, чтобы избежать тесной связи с Eloquent.

---

### 🔄 4. **Strategy (Стратегия)**

**Когда использовать:**  
Когда нужно **сменить поведение объекта во время выполнения**.

**Пример:**

```php
interface PaymentStrategy {
    public function pay($amount);
}

class PaypalPayment implements PaymentStrategy {
    public function pay($amount) { echo "Pay $amount with PayPal"; }
}

class CardPayment implements PaymentStrategy {
    public function pay($amount) { echo "Pay $amount with Card"; }
}

class Checkout {
    public function __construct(private PaymentStrategy $strategy) {}

    public function process($amount) {
        $this->strategy->pay($amount);
    }
}
```

**Laravel-пример:**  
Выбор логики в зависимости от настроек/типа объекта:

```php
$payment = new Checkout(new PaypalPayment());
```

---

### 🔍 Где это встречается в Laravel:

|Паттерн|Где используется в Laravel|
|---|---|
|**Factory**|`app()->make(...)`, фабрики моделей (`factory()`)|
|**Singleton**|`app()->singleton(...)`, `config()`|
|**Repository**|Кастомные репозитории в Domain-Driven Design|
|**Strategy**|`NotificationChannel`, `Auth Guard`, `ValidationRule`|

### 💡 Подсказка студентам:

- Паттерны — не "золотое правило", а **инструмент**, и нужно знать **когда применять**  
- Один и тот же код можно **по-разному улучшить** с помощью разных шаблонов
