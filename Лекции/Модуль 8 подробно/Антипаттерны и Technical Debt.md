
## 🔷 0:38–0:45 — **Антипаттерны и технический долг (technical debt)** + Q&A

**Цель:**  
Научить студентов **узнавать плохие архитектурные решения** и **не создавать их в своих проектах**. Объяснить, что такое технический долг и почему его важно контролировать.

---

### 🛑 Что такое антипаттерн?

**Антипаттерн** — это решение, которое **кажется удобным**, но **в долгосрочной перспективе приводит к проблемам**: плохая читаемость, жёсткая связность, тестируемость, баги.

---

## ⚠️ 1. **God Object (Бог-объект)**

**Признаки:**

- Огромный класс (1000+ строк)  
- Знает всё и делает всё  
- Нарушает SRP (Single Responsibility)  

**Проблемы:**

- Любое изменение вызывает лавину багов  
- Зависимости — десятки, невозможно тестировать  

**Пример:**

```php
class Application {
    public function handleRequest() { ... }
    public function sendEmail() { ... }
    public function createUser() { ... }
    public function logError() { ... }
    public function sendSms() { ... }
}
```

**Как исправить:**

- Разбить на отдельные сервисы: `RequestHandler`, `EmailService`, `UserService`, `Logger`, `SmsSender`  

---

## 🍝 2. **Spaghetti Code (макароны)**

**Признаки:**

- Много `if`, `else`, `switch`, вложенных циклов  
- Нет архитектуры — только последовательный поток  
- Повторение одного и того же кода (копипаст)  

**Пример:**

```php
if ($type == 'admin') {
    // логика
} elseif ($type == 'editor') {
    // логика
} elseif (...) {
    ...
}
```

**Как исправить:**

- Использовать Strategy  
- Делегировать поведение объектам  
- Убрать дублирование  

---

## 💉 3. **Active Record на стероидах**

**Что это значит:**

- Когда Eloquent-модель содержит всё подряд:
    - Бизнес-логику  
    - Правила валидации  
    - Вывод HTML  
    - API-сериализацию  

```php
class User extends Model {
    public function isAdmin() { ... }
    public function toHtml() { ... } // ❌
    public function calculateDiscount() { ... } // ❌
}
```

**Проблема:**

- **Сильная связность**, сложно повторно использовать 
- Модель становится "бог-объектом"  

**Решение:**

- Выделять сервисы (`DiscountCalculator`, `UserHtmlPresenter`)  
- Использовать репозитории и стратегии

## 💣 Что такое Technical Debt (технический долг)?

**Определение:**  
Это **компромиссы в коде, принятые ради скорости**, но требующие доработки в будущем.

**Примеры:**

- Быстро написали фичу без тестов  
- Жёстко захардкодили условие  
- Использовали глобальные переменные  
- Скопировали и вставили, не думая  

---

### 📉 К чему приводит технический долг?

- Снижается скорость разработки  
- Становится страшно "трогать" старый код  
- Новым разработчикам сложно разобраться  
- Повышается риск багов  

---

### 🔄 Как контролировать техдолг:

- Использовать **линтеры, статический анализ**  
- Писать тесты (даже базовые)  
- Оформлять TODO с пометкой о возврате  
- Периодически делать **рефакторинг**
