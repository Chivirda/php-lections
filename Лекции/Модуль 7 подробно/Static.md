
## 🔹 0:35–0:45 — **Static: статические свойства и методы, счёт экземпляров, синглтон (как антипаттерн)**

### 📌 Цель блока:

Показать, как использовать статические свойства и методы в PHP, объяснить разницу между ними и обычными (нестатическими), и предостеречь от чрезмерного увлечения шаблоном Singleton.

---

### 📖 Теория

#### 🧩 Что такое `static`

**Статическое свойство или метод** принадлежит **классу**, а не конкретному объекту.  
То есть не нужно создавать объект, чтобы обратиться к ним.

```php
class Math {
    public static float $pi = 3.14;

    public static function square(float $x): float {
        return $x * $x;
    }
}

echo Math::$pi;             // 3.14
echo Math::square(5);       // 25
```

---

### 🧱 Отличия статических и обычных:

|Особенность|Обычное (нестатическое)|Статическое|
|---|---|---|
|Принадлежит|Объекту|Классу|
|Вызывается|`$obj->method()`|`Class::method()`|
|Ключевое слово|`$this`|`self::` или `static::`|
|Требует экземпляр класса|✅|❌|
|Можно переопределять|Да (через наследование)|Часто нет, если `final`|

---

### 📈 Пример: Счётчик экземпляров

```php
class User {
    public static int $count = 0;

    public function __construct() {
        self::$count++;
    }
}

new User();
new User();
echo User::$count; // 2
```

Статическое свойство `$count` считает, сколько объектов создано.

---

### 🧪 Пример: Вспомогательные методы (utility)

```php
class StringHelper {
    public static function slugify(string $text): string {
        return strtolower(str_replace(" ", "-", trim($text)));
    }
}

echo StringHelper::slugify("Hello World"); // hello-world
```

---

### ⚠️ Синглтон — антипаттерн

Синглтон — это шаблон, который ограничивает создание объекта **одним экземпляром**. Часто используется так:

```php
class Logger {
    private static ?Logger $instance = null;

    private function __construct() {}

    public static function getInstance(): Logger {
        if (self::$instance === null) {
            self::$instance = new Logger();
        }
        return self::$instance;
    }
}
```

---

#### ❗ Почему синглтон считается **антипаттерном**?

- **Скрытая глобальная переменная**.
- **Нарушает SRP (принцип единственной ответственности)**.
- **Плохо тестируется**: сложно подменить `getInstance()` в тестах.
- **Трудно управлять зависимостями**: нарушает принципы DI (внедрения зависимостей).

### ❓ Чем отличается `self::` от `$this->`?

**Ответ:**

|Конструкция|Что делает|Где используется|
|---|---|---|
|`$this->`|Обращается к **экземпляру** объекта (нестатические свойства и методы)|Внутри обычных (нестатических) методов|
|`self::`|Обращается к **классу**, а не объекту. Используется для статических свойств и методов|Внутри **статических и нестатических методов**|

Пример:

```php
class Example {
    public static $x = 10;
    public $y = 20;

    public function showY() {
        echo $this->y;      // OK
    }

    public static function showX() {
        echo self::$x;      // OK
        // echo $this->y;   // ❌ Ошибка: $this нельзя использовать в static
    }
}
```

---

### ❓ Можно ли использовать `$this` внутри `static` метода?

**Ответ:**  
**Нет, нельзя.** `$this` указывает на экземпляр объекта, а `static`-метод вызывается **без создания экземпляра**.

**Что будет:**

```php
class A {
    public static function foo() {
        echo $this->bar; // ❌ Ошибка: $this не доступен
    }
}
```

Внутри `static`-методов используется `self::` или `static::` для доступа к другим `static`-членам.

---

### ❓ Когда использовать `static` свойства и методы?

**Ответ:**  
Используйте `static`, когда:

- Свойство или метод **не зависят от конкретного объекта**.
- Нужно **общее состояние** для всех объектов (например, счётчик экземпляров).
- Создаёте **утилитарные методы** (например, `Math::sqrt()`, `StringHelper::slugify()`).
- Хочется обращаться к функции **без создания объекта**.

**Примеры:**

- `Config::get('db.host')`
- `DateTime::createFromFormat(...)`

⚠️ **Не стоит использовать `static` по привычке** — это усложняет тестирование и снижает гибкость кода.

---

### ❓ Почему статическая переменная — это не всегда хорошее решение?

**Ответ:**  
Потому что:

- Статическое состояние **глобально**, и его **сложно контролировать**.
- При тестировании и повторных вызовах **значения сохраняются** между вызовами — это может привести к **побочным эффектам**.
- Нарушается **инкапсуляция** — поведение может зависеть от предыдущих вызовов (как в глобальных переменных).
- Зависимости становятся **неявными** — код "волшебным образом" работает, но непонятно почему.

**Лучше использовать:**  
внедрение зависимостей через конструктор (`Dependency Injection`), а не напрямую тянуть `Logger::getInstance()`.
