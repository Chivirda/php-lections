
## 🔹 0:25–0:35 — **Модификаторы доступа: `public`, `protected`, `private`. Зачем нужна инкапсуляция**

### 📌 Цель блока:

Показать, как ограничивать доступ к свойствам и методам с помощью модификаторов доступа. Объяснить принцип инкапсуляции и зачем она нужна для безопасного и контролируемого кода.

---

### 📖 Теория

#### 🔓 Модификаторы доступа

|Модификатор|Доступен…|Пример использования|
|---|---|---|
|`public`|Откуда угодно|`$object->property`|
|`protected`|Внутри класса и его потомков|`parent::method()`|
|`private`|Только внутри текущего класса|`$this->property` внутри класса|

---

### 🧱 Пример

```php
class BankAccount {
    private float $balance = 0;

    public function deposit(float $amount): void {
        if ($amount > 0) {
            $this->balance += $amount;
        }
    }

    public function getBalance(): float {
        return $this->balance;
    }
}
```

```php
$account = new BankAccount();
$account->deposit(1000);
echo $account->getBalance(); // 1000

// $account->balance = 1_000_000; ❌ Ошибка: свойство private
```

### 🧠 Зачем нужна инкапсуляция?

**Инкапсуляция** — это принцип ООП, который позволяет:

- **Скрыть** внутренние детали реализации.
- Защитить объект от **некорректного использования**.
- Изменять реализацию без риска, что кто-то напрямую обращается к полям.

Это как капот у машины: водитель не может напрямую менять работу двигателя, он нажимает на педали, а как это работает — внутри «инкапсулировано».

---

### ⚠️ Ошибки, которых стоит избегать:

|Ошибка|Почему плохо|
|---|---|
|Делать все свойства `public`|Нарушение инкапсуляции, уязвимость|
|Прямой доступ к внутренним данным извне|Труднее отследить изменения|
|Отсутствие `get/set`-методов при необходимости|Нет контроля за вводимыми значениями|

---

### ✅ Хорошая практика: `get()` и `set()` методы

```php
class User {
    private string $email;

    public function setEmail(string $email): void {
        if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
            throw new InvalidArgumentException("Неверный email");
        }
        $this->email = $email;
    }

    public function getEmail(): string {
        return $this->email;
    }
}
```

---

### 🧪 Мини-кейс: Инкапсуляция и контроль

```php
class TemperatureSensor {
    private float $temperature = 0;

    public function setTemperature(float $temp): void {
        if ($temp < -100 || $temp > 150) {
            throw new InvalidArgumentException("Неверный диапазон");
        }
        $this->temperature = $temp;
    }

    public function getTemperature(): float {
        return $this->temperature;
    }
}
```

Теперь нельзя напрямую задать абсурдную температуру.

### ❓ Почему нельзя использовать `public` везде?

**Ответ:**  
Потому что это нарушает принцип инкапсуляции и делает объект уязвимым.  
Если все свойства будут публичными, любой внешний код сможет менять их напрямую, в обход проверки или логики, что приводит к:

- **непредсказуемому поведению** объекта;
- **трудностям в отладке и сопровождении**;
- **невозможности контролировать допустимые значения**;
- **повышенному риску багов и уязвимостей**.

**Пример плохой практики:**

```php
$user->email = "not-an-email"; // без валидации
```

Лучше использовать `private` или `protected`, и предоставить методы `getEmail()` / `setEmail()` с проверками.

---

### ❓ Когда использовать `protected`?

**Ответ:**  
Когда нужно скрыть свойство или метод от внешнего мира, но разрешить доступ **потомкам (наследникам)**.

Используется, если:

- Вы проектируете базовый класс, который должен **давать гибкость наследникам**, но **не внешнему коду**.
- Нужно **расширять поведение в подклассах**, но **не допускать прямой доступ извне**.

**Пример:**

```php
class Animal {
    protected function breathe() {
        echo "Вдох...";
    }
}

class Dog extends Animal {
    public function run() {
        $this->breathe(); // допустимо, потому что метод protected
    }
}
```

### ❓ Какой модификатор по умолчанию, если не указать явно?

**Ответ:**  
В PHP модификатор доступа **по умолчанию — `public`**.

Пример:

```php
class MyClass {
    function test() {
        echo "Hello!";
    }
}
```

Метод `test()` будет считаться `public`, хотя явно не указан.

⚠️ **Совет:** всегда **указывай модификаторы явно** — это повышает читаемость и снижает ошибки.
