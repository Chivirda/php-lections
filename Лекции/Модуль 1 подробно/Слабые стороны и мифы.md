
## 🔻 Миф 1: «PHP — это медленно»

### Почему этот миф появился:

- Исторически, **PHP 4 и 5** действительно работали медленно по сравнению с Java или C++.
- Не было компиляции, всё интерпретировалось на каждый запрос.
- Разработка часто велась без кэширования, с копипастой кода и тяжёлыми циклами.

### Что изменилось:

#### ✅ **OPcache (с PHP 5.5+)**

- Это встроенный механизм, который **кэширует байткод PHP-файлов**, чтобы не компилировать их заново при каждом запросе.
- Значительно ускоряет запуск приложений.
- Включается одной строкой в `php.ini`:
```ini
opcache.enable=1
```

#### ✅ **JIT (Just-in-Time Compiler) — с PHP 8.0**

- Позволяет PHP-коду компилироваться в машинный код во время выполнения.
- Особо эффективен в вычислительно тяжёлых задачах: циклы, математика, рекурсия.
- Примерно на **10–30%** быстрее в типовых кейсах.
- Можно настроить уровень агрессии JIT:
```ini
opcache.jit=1255
```


📌 **Вывод:** сегодня PHP работает **достаточно быстро**, особенно для задач типа CRUD/API.

## 🔻 Миф 2: «PHP — это спагетти-код»

### Что такое спагетти-код:

- Перемешанный HTML и PHP в одном файле.
- Копипаста без функций и классов.
- Нет архитектуры, логики, шаблонов.

### Почему этот миф появился:

- В 2000–2010 годах многие создавали сайты на PHP без опыта.
- Были популярны CMS с грязным кодом: старые версии Joomla, WordPress, самописки.
- Сам язык не имел строгих требований (до PHP 7 даже типизация была формальной).

### Что изменилось:

#### ✅ Современные фреймворки (Laravel, Symfony)

- Жёсткое разделение логики: MVC (Model–View–Controller).
- Использование шаблонизаторов (Blade, Twig).
- Контейнер зависимостей, миграции, роутинг, тестирование.

#### ✅ Composer и автозагрузка

- Composer — как npm или pip: чёткая структура и зависимости.
- PSR-4 автозагрузка классов:

```json
"autoload": {
    "psr-4": {
		"App\\": "app/"
   }
}
```


#### ✅ PSR — PHP Standard Recommendations

- **PSR-1, PSR-2, PSR-12** — стандарты форматирования и стиля кода.
- **PSR-4** — стандарт автозагрузки.
- **PSR-7** — стандартизированный HTTP-запрос и ответ.
- **PSR-11** — контейнер зависимостей.

📌 **Вывод:** спагетти-код — не проблема языка, а подхода. Современный PHP-код может быть **чистым, читаемым и строго структурированным**.

## 🔻 Другие предрассудки

### ❌ «PHP — устаревший язык»

- Реальность: **язык активно развивается**, каждая новая версия приносит улучшения.
- В PHP 8+: named arguments, union types, match expression, JIT.

### ❌ «На PHP не делают серьёзные проекты»

- Примеры:
    - **Facebook** начинался на PHP (сейчас работает через HHVM, но корень в PHP).
    - **Wikipedia**, **Slack (частично)**, **Mailchimp**, **WordPress.com** — используют PHP.
    - Большинство крупных CMS — на PHP.

## 🧠 Что сказать студентам:

**PHP = быстрый старт + зрелая платформа + плохая репутация в прошлом.**  
Но сегодня он:

- Быстрый (JIT, OPcache),
- Стандартизированный (PSR),
- Организованный (Composer, MVC),
- Тестируемый (PHPUnit, Pest),
- Идеален для web-разработки с быстрым результатом.
