
## 🔹 0:20–0:35 — Контроллеры

### 🎯 **Цель блока**

Показать, как использовать контроллеры в Laravel для отделения логики от маршрутов и создания REST-интерфейсов.

---

### 🧩 **Что такое контроллер?**

Контроллер — это класс, который содержит методы, обрабатывающие определённые маршруты. Контроллеры упрощают структуру проекта и делают код более читаемым и масштабируемым.

---

### ✅ **Создание контроллера**

#### 📌 Базовый контроллер:

```bash
php artisan make:controller HelloController
```

Создаст файл `app/Http/Controllers/HelloController.php`:

```php
namespace App\Http\Controllers;

use Illuminate\Http\Request;

class HelloController extends Controller
{
    public function index() {
        return 'Hello from controller!';
    }
}
```

**Маршрут:**

```php
Route::get('/hello', [HelloController::class, 'index']);
```

---

### 📌 **Контроллер с REST-методами:**

```bash
php artisan make:controller PostController --resource
```

Создаст контроллер со следующими методами:

|Метод контроллера|HTTP|URI|Назначение|
|---|---|---|---|
|`index()`|GET|/posts|список|
|`create()`|GET|/posts/create|форма создания|
|`store()`|POST|/posts|сохранение|
|`show($id)`|GET|/posts/{id}|просмотр|
|`edit($id)`|GET|/posts/{id}/edit|редактирование|
|`update($id)`|PUT/PATCH|/posts/{id}|обновление|
|`destroy($id)`|DELETE|/posts/{id}|удаление|

#### 👇 Ресурсный маршрут:

```php
Route::resource('posts', PostController::class);
```

> Laravel сам сгенерирует все маршруты, привязанные к этим методам.

---

### 📌 **Single Action Controller (одно-действенный)**

Если нужен контроллер только с одним методом:

```bash
php artisan make:controller WelcomeController --invokable
```

Класс будет выглядеть так:

```php
class WelcomeController extends Controller
{
    public function __invoke()
    {
        return 'Welcome!';
    }
}
```

**Роут:**

```php
Route::get('/welcome', WelcomeController::class);
```

> Такой подход удобен, когда контроллер делает одно дело (например, отображает страницу или обрабатывает форму).

---

### 🧠 **Зачем использовать контроллеры?**

- **Читаемость**: маршруты становятся лаконичными.
- **Переиспользуемость**: методы можно вызывать из других частей кода.
- **Тестируемость**: удобно писать юнит-тесты.
- **Разделение ответственности**: маршруты не перегружаются логикой.

---

### 🧪 **Интерактивное задание:**

> "Создайте контроллер `HelloController` с методом `say`, который возвращает `Hello, {name}`. Используйте его в маршруте с параметром."

```bash
php artisan make:controller HelloController
```

```php
// HelloController.php
public function say($name) {
    return "Hello, $name!";
}
```

```php
// routes/web.php
Route::get('/hello/{name}', [HelloController::class, 'say']);
```

---
Отличное замечание — ты абсолютно прав: **ресурсный контроллер (resource controller)** в Laravel **может нарушать принцип единой ответственности (Single Responsibility Principle, SRP)** из SOLID-принципов.

---

## 🔎 В чём проблема?

### 📌 Принцип единой ответственности (SRP):

> Класс должен иметь **только одну причину для изменения** — то есть отвечать **за одну вещь**.

---

### 📛 А теперь посмотрим на типичный `PostController`:

```php
class PostController extends Controller
{
    public function index()      { /* показать все посты */ }
    public function create()     { /* показать форму создания */ }
    public function store()      { /* сохранить пост */ }
    public function show($id)    { /* показать один пост */ }
    public function edit($id)    { /* показать форму редактирования */ }
    public function update($id)  { /* обновить пост */ }
    public function destroy($id) { /* удалить пост */ }
}
```

Этот контроллер:

- выводит списки,
- обрабатывает формы,
- отвечает за сохранение в БД,
- удаляет ресурсы…

👉 **То есть, у него сразу несколько "поводов для изменений":**

- меняется логика сохранения? → правим `store()`
- новое оформление формы? → правим `create()` / `edit()`
- меняется фильтрация? → правим `index()`

---

## 🤯 Это делает `PostController` перегруженным

Особенно при реальной разработке:

- появляются проверки прав,
- валидация усложняется,
- надо логировать действия,
- нужно добавлять кэширование, события, нотификации...

❗ Всё это оказывается в одном огромном классе.

---

## ✅ Как это улучшить?

Вот 3 практики, чтобы **соблюсти SRP в Laravel**:

### 1. 🔹 **Разделение по задачам (контекстам)**

Разделите один ресурсный контроллер на _несколько_:

```php
// вместо одного PostController:
- PostViewController   (index, show)
- PostEditController   (edit, update)
- PostCreateController (create, store)
- PostDeleteController (destroy)
```

Это verbose, но лучше масштабируется.

---

### 2. 🔹 **Вынесение логики в сервисы**

Контроллер остаётся тонким:

```php
public function store(StorePostRequest $request)
{
    $this->postService->create($request->validated());
    return redirect()->route('posts.index');
}
```

Сама логика (валидация, бизнес-решения, создание моделей, события) живёт в отдельном `PostService`.

---

### 3. 🔹 **Использование Action-классов**

Ещё один шаблон: один класс — одно действие.

```bash
app/Actions/Post/CreatePost.php
app/Actions/Post/UpdatePost.php
```

Контроллер вызывает нужный action-класс:

```php
public function store(StorePostRequest $request)
{
    (new CreatePost())->handle($request->validated());
}
```

## 💬 Вывод

|✅ Ресурсные контроллеры|🚫 Потенциальные проблемы|
|---|---|
|Быстро scaffold-ить CRUD|Нарушение SRP|
|Хороши для MVP и обучения|Сложно поддерживать в больших проектах|
|Совместимы с `Route::resource`|Логика может смешиваться|

> **Рекомендация:** Используй ресурсные контроллеры как старт, но не бойся **рефакторить** и **делить** логику, как только она выходит за рамки простого CRUD.

---

Отлично. Ниже ты увидишь пример **перегруженного ресурсного контроллера**, а затем — его **разбиение на сервис и Form Request** для соблюдения принципа единой ответственности (SRP).

## ❌ Перегруженный ресурсный контроллер (антипаттерн)

```php
namespace App\Http\Controllers;

use App\Models\Post;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;

class PostController extends Controller
{
    public function store(Request $request)
    {
        // Валидация
        $validated = $request->validate([
            'title' => 'required|string|max:255',
            'body' => 'required|string|min:10',
        ]);

        // Логика создания
        $post = new Post();
        $post->title = $validated['title'];
        $post->body = $validated['body'];
        $post->user_id = Auth::id();
        $post->save();

        // Отправка уведомлений (побочный эффект)
        \Notification::route('mail', 'admin@example.com')
            ->notify(new \App\Notifications\PostCreated($post));

        return redirect()->route('posts.index')
            ->with('success', 'Пост создан!');
    }
}
```

🔴 Здесь **всё перемешано**:

- валидация
- бизнес-логика
- работа с моделью
- побочные эффекты (нотификации)
- редирект и сессия

## ✅ Разделение на компоненты

### 1. 📦 **Form Request**: `StorePostRequest.php`

```bash
php artisan make:request StorePostRequest
```

```php
namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class StorePostRequest extends FormRequest
{
    public function rules(): array
    {
        return [
            'title' => 'required|string|max:255',
            'body' => 'required|string|min:10',
        ];
    }
}
```

---

### 2. 🛠 **Сервис**: `PostService.php`

```php
namespace App\Services;

use App\Models\Post;
use Illuminate\Support\Facades\Auth;

class PostService
{
    public function create(array $data): Post
    {
        $post = Post::create([
            'title'    => $data['title'],
            'body'     => $data['body'],
            'user_id'  => Auth::id(),
        ]);

        \Notification::route('mail', 'admin@example.com')
            ->notify(new \App\Notifications\PostCreated($post));

        return $post;
    }
}
```

---

### 3. 📋 **Контроллер**: `PostController.php`

```php
namespace App\Http\Controllers;

use App\Http\Requests\StorePostRequest;
use App\Services\PostService;

class PostController extends Controller
{
    public function __construct(protected PostService $postService) {}

    public function store(StorePostRequest $request)
    {
        $this->postService->create($request->validated());

        return redirect()->route('posts.index')
            ->with('success', 'Пост создан!');
    }
}
```

---

## 🔍 Что мы получили?

|До|После|
|---|---|
|1 перегруженный метод `store()`|1 thin controller, 1 Form Request, 1 Service|
|Смешение ответственности|SRP: каждый компонент делает 1 вещь|
|Трудно тестировать|Можно тестировать сервисы отдельно|
|Не читаемо|Чистая архитектура|

---

## ❔ Когда рефакторить ресурсные контроллеры?

**Если:**

- логика выходит за рамки 10–15 строк,
- появляются побочные эффекты (нотификации, логи, события),
- валидация и правила усложняются,
- контроллер начинает «разрастаться» до 300+ строк.

**→ Рефакторь.**
