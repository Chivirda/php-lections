## ✅ 1. Artisan — сердце Laravel из консоли

### 📋 Что такое Artisan?

- Это командный интерфейс для управления Laravel-проектом.
- Включает команды для генерации кода, миграций, работы с очередями, кэшем, тестами и многого другого.

### 📄 Базовые команды:

|Команда|Назначение|
|---|---|
|`php artisan list`|Показать список всех команд|
|`php artisan help make:model`|Документация по команде|
|`php artisan serve`|Встроенный веб-сервер|
|`php artisan route:list`|Список маршрутов|
|`php artisan migrate`|Запуск миграций|
|`php artisan make:controller`|Генерация контроллера|
|`php artisan tinker`|REPL-оболочка для работы с кодом|

### 📦 Полезно в реальной разработке:

- быстро посмотреть маршруты;
- прогнать сидеры, миграции;
- отладить Eloquent в tinker;
- сбросить кеш маршрутов, конфигов, view.

## ✅ 2. Экосистема Laravel

### 📦 Horizon

- Панель мониторинга для **очередей** (jobs, workers).
- Красивый веб-интерфейс для отслеживания выполнения заданий.
- Команда запуска: `php artisan horizon`.

### 📦 Scout

- Пакет для **поискового индекса** (Full-Text Search).
- Работает с Algolia, Meilisearch, Elasticsearch.
- Легко интегрируется с Eloquent-моделями.

### 📦 Livewire

- Пакет для **динамических интерфейсов без JS**.
- Пишем компоненты на PHP → Livewire обновляет DOM.
- Удобен для форм, таблиц, интерактивных интерфейсов.

### 📦 Breeze, Jetstream, Fortify

- **Breeze**: минимальная auth-стартовая сборка.
- **Jetstream**: готовая аутентификация с профилями, API tokens.
- **Fortify**: backend-only аутентификация.

### 📦 Laravel Echo & Websockets

- Реалтайм-обновления через websockets.
- Используется с Pusher или собственным сервером.

## ✅ 4. Artisan & кастомные команды

```bash
php artisan make:command SendReports
```

Выполняются через:

```bash

```

## 🔶 1. **Зачем кешировать маршруты?**

### Причина:

- При каждом запросе Laravel **чтёт файлы маршрутов (`routes/web.php`, `api.php`)** и собирает их в массив.
- В больших проектах это замедляет отклик приложения.

### Кеширование маршрутов (`php artisan route:cache`):

- Laravel **один раз собирает маршруты** и сохраняет в файл `bootstrap/cache/routes-v7.php`.
- При следующих запросах маршруты загружаются мгновенно (без парсинга).

### ➡ Итог:

- В продакшене кеш обязателен.
- В dev-среде кеш отключают, чтобы видеть изменения.

## 🔶 2. **Чем фасад в Laravel отличается от фасада в паттерне GoF?**

### Паттерн Facade (GoF):

- Это **структурный паттерн**, который предоставляет **упрощённый интерфейс к сложной подсистеме**.
- Пример: класс, который упрощает работу с несколькими сервисами.

### Фасады в Laravel:

- Это **статический синтаксис для сервисов из Service Container**.
- Под капотом — это **динамический вызов метода у реального объекта через контейнер зависимостей**.
- На самом деле, Laravel фасад — это больше **Proxy + Dependency Injection + Static Proxy**, чем чистый Facade по GoF.

### ➡ Ключевое отличие:

|GoF|Laravel|
|---|---|
|Упрощённый интерфейс к подсистеме|Упрощённый доступ к сервисам из контейнера|
|"Обёртка" над несколькими классами|"Обёртка" над binding в Service Container|
|Чистая структурная композиция|Синтаксический сахар над DI|

## 🔶 3. **В чём польза Service Container для больших проектов?**

### Проблема без контейнера:

- Вручную передавать зависимости → много дублирования.
- Сильно связанные классы.
- Сложно тестировать (mock'и приходится подменять вручную).

### Service Container Laravel:

- **Автоматически внедряет зависимости** через конструктор или метод.
- Позволяет **легко заменять реализации интерфейсов**.
- Упрощает **тестирование (mocking)**.
- Позволяет регистрировать синглтоны, фабрики, условия.

### ➡ В больших проектах:

|Без контейнера|С контейнером|
|---|---|
|"new" в каждом классе|Автоматический DI|
|Сильно связанные зависимости|Слабосвязанные абстракции|
|Ручная инициализация|Автоматическая|
|Трудно тестировать|Легко мокировать|

## 🔶 4. **Когда стоит переходить с Blade на Livewire или Inertia?**

### Blade:

- Отлично подходит для **статичных страниц**, форм, простого CRUD.
- Хорош, когда JS не нужен или нужен минимально.

### Когда переходить на **Livewire**:

- Нужно сделать **интерактивные элементы без написания JS**.
- Примеры: фильтры в реальном времени, сортировки, динамические формы.
- Если команда PHP-разработчиков хочет динамику без Vue/React.

### Когда переходить на **Inertia.js**:

- Если нужно полноценное **SPA-приложение** (с Vue или React).
- Под капотом всё ещё Laravel, но фронтенд рендерится как SPA.
- Идеально для админок, личных кабинетов.

### ➡ Кратко:

|Blade|Livewire|Inertia|
|---|---|---|
|Статичные страницы, формы|Динамические компоненты без JS|Полноценный SPA с Vue/React|
|Серверный рендеринг|Серверный рендеринг с live-обновлением|SPA-опыт, без API|
|Легко и просто|Легко для PHP-разработчиков|Лучше для JS heavy UI|

---

### 🔔 Резюме:

- Blade → стартовый уровень.
- Livewire → лёгкий интерактив без SPA.
- Inertia → полноценный SPA на Laravel.
