
### ⏰ **0:12–0:22** — **`try / catch / finally` в PHP**

#### 🎯 Цель блока:

Научить студентов **перехватывать и обрабатывать ошибки**, используя конструкции `try`, `catch`, `finally`, а также правильно применять `??` и `throw` в логике.

---

### 📚 Теория:

#### 🔹 Основная конструкция:

```php
try {
    // Код, который может вызвать исключение
} catch (ExceptionType $e) {
    // Обработка исключения
} finally {
    // Код, который выполняется в любом случае (необязательный блок)
}
```

- `try` — блок, в котором может произойти исключение.
- `catch` — обрабатывает исключение определённого типа.
- `finally` — всегда выполняется, даже если:
    - было исключение,
    - был `return` или `exit`.

---

### 🧪 Пример:

```php
function divide($a, $b) {
    if ($b === 0) {
        throw new DivisionByZeroError("На ноль делить нельзя");
    }
    return $a / $b;
}

try {
    echo divide(10, 0);
} catch (DivisionByZeroError $e) {
    echo "Ошибка: " . $e->getMessage();
} finally {
    echo "\nБлок finally всегда отработает!";
}
```

**Вывод:**

```
Ошибка: На ноль делить нельзя
Блок finally всегда отработает!
```

---

### 🔹 Несколько `catch`:

Можно перехватывать разные исключения по типу:

```php
try {
    // ...
} catch (ValidationException $e) {
    // Специфичная обработка
} catch (\Throwable $e) {
    // Общая обработка
}
```

> Порядок `catch` имеет значение: от специфичного к более общему!

---

### 🔹 `throw` и повторное выбрасывание:

Иногда нужно логировать и **перебросить** исключение дальше:

```php
try {
    // ...
} catch (SomeException $e) {
    logError($e);
    throw $e;
}
```

---

### 🔹 Сравнение с `??` (null coalescing):

Иногда **исключения не нужны**, если можно использовать безопасное значение:

```php
$userEmail = $_POST['email'] ?? 'no-email@example.com';
```

Это **альтернатива выбрасыванию исключения**, когда можно подставить значение по умолчанию.

---

### 🔍 Заметки для студентов:

- В `catch` можно использовать **типизацию**, чтобы обрабатывать разные ошибки отдельно.
- `finally` удобен для **освобождения ресурсов**: файлов, соединений, кэширования.
- Избегай пустых `catch` — всегда **логируй или обрабатывай**.

---

### 🧑‍💻 Ещё один пример:

```php
function readFileSafe($filename) {
    try {
        if (!file_exists($filename)) {
            throw new \RuntimeException("Файл не найден");
        }
        return file_get_contents($filename);
    } catch (\RuntimeException $e) {
        return "Ошибка: " . $e->getMessage();
    } finally {
        echo "\n[Файл: $filename обрабатывался]";
    }
}

echo readFileSafe("missing.txt");
```

Вот ответы на вопросы из предыдущего блока:

---

### ❓ **1. Когда использовать `finally`, а когда просто `catch`?**

- **`catch`** используется, чтобы **обработать исключение**: показать сообщение, вернуть ошибку, залогировать проблему.
- **`finally`** применяется, чтобы **выполнить действия в любом случае**, даже если исключения не было:
    - закрытие соединений,
    - очистка временных файлов,
    - освобождение ресурсов.
- **Пример:**

```php
try {
	$conn = connect();
	runQuery($conn);
} catch (\Throwable $e) {
	logError($e);
} finally {
	$conn->close(); // Гарантированно выполнится
}
```


---

### ❓ **2. Почему полезно логировать перед `re-throw`?**

- Без логирования ошибка может **пройти незамеченной**.
- Лог помогает **отладить проблему** или собрать статистику.
- `re-throw` — это сигнал: _"я не могу справиться, но я сообщил о проблеме"_.
- **Пример:**

```php
catch (\Exception $e) {
	error_log($e);
	throw $e; // Отправляем ошибку выше
}
```

---

### ❓ **3. Чем отличается `??` от `isset()`?**

- `??` — оператор **null coalescing**, вернёт **первое не-null значение**:
```php
$email = $_POST['email'] ?? 'guest@example.com';
```

- `isset()` — функция, проверяет только наличие переменной и **не равна ли она null**, но **не возвращает значение**:

```php
if (isset($_POST['email'])) {
	$email = $_POST['email'];
} else {
	$email = 'guest@example.com';
}
```

- `??` проще и короче. Работает даже с цепочками:

```php
$name = $user['profile']['name'] ?? 'Аноним';
```


---

### ❓ **4. Что произойдёт, если исключение не перехвачено (`catch` не сработал)?**

- Скрипт завершится **фатальной ошибкой**.
- PHP отобразит **трассировку стека (stack trace)** — путь к месту ошибки.
- Если настроен глобальный обработчик ошибок (`set_exception_handler`), он будет вызван.
- В боевых приложениях без `catch` это = **500 Internal Server Error**.

**Вывод:** всегда оборачивай потенциально опасный код в `try/catch`, особенно в местах:

- доступа к БД,
- сетевых запросов,
- работы с файлами,
- внешних API.
