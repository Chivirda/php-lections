
### ⏰ **0:22–0:32** — **Строгая типизация в PHP**

#### 🎯 Цель блока:

Научить студентов использовать современные механизмы типизации в PHP: `strict_types`, типизированные свойства, объединения (`union`), пересечения (`intersection`), `readonly` и `enum`. Показать, как это делает код предсказуемым и само-документируемым.

---

### 📚 Теория:

#### 🔹 `declare(strict_types=1);`

- Включает **строгую типизацию аргументов и возвращаемых значений**.
- Без этого PHP может выполнять **автоматическое приведение типов** (например, строка в число).

```php
declare(strict_types=1);

function add(int $a, int $b): int {
    return $a + $b;
}

echo add("5", 2); // ❌ Fatal error, если strict_types=1
```

> 📝 `declare(strict_types=1);` должен быть **первой строкой** в PHP-файле (после `<?php`).

---

#### 🔹 Типизированные свойства классов (PHP 7.4+)

```php
class User {
    public int $id;
    public string $name;
}
```

- Ошибка произойдёт, если попытаться присвоить неправильный тип:
```php
$user = new User();
$user->id = 'abc'; // ❌ TypeError
```

---

#### 🔹 `union types` (PHP 8.0+)

Тип может быть **одним из нескольких**:

```php
function sum(int|float $a, int|float $b): float {
    return $a + $b;
}
```

- Удобно, когда функция может работать с несколькими типами, но всё равно с контролем.

---

#### 🔹 `intersection types` (PHP 8.1+)

Тип должен реализовывать **все указанные интерфейсы**:

```php
function process(Countable&Iterator $item) {
    foreach ($item as $v) { /* ... */ }
}
```

- Используется редко, но важно для **работы с абстракциями**.

---

#### 🔹 `readonly` свойства (PHP 8.1+)

- Можно задать **только один раз**, обычно в `__construct`.

```php
class Config {
    public readonly string $env;

    public function __construct(string $env) {
        $this->env = $env;
    }
}
```

- Попытка изменить свойство — ошибка:
```php
$cfg->env = "prod"; // ❌ Error
```

---

#### 🔹 `enum` (PHP 8.1+)

- Заменяет «магические строки» и `const`-массивы.
- Используется для **ограниченных множеств значений**.

```php
enum Status {
    case Draft;
    case Published;
    case Archived;
}

function setStatus(Status $status) {
    echo "Новый статус: $status->name";
}
```

> Это безопасно, удобно в API, особенно при валидации.

---

### 🧑‍💻 Live-код:

```php
declare(strict_types=1);

enum Status {
    case Draft;
    case Published;
}

class Article {
    public readonly string $title;
    public Status $status;

    public function __construct(string $title) {
        $this->title = $title;
        $this->status = Status::Draft;
    }
}

$article = new Article("Современный PHP");
$article->status = Status::Published;

echo "{$article->title} → {$article->status->name}"; // Современный PHP → Published
```

---

### ❗ Подводные камни и советы:

- `readonly` — только один раз на весь жизненный цикл.
- Строгая типизация **не защищает от логических ошибок**, но **минимизирует типовые баги**.
- `enum` нельзя расширить (final по сути), но можно добавлять методы.

## ✅ Ответы на вопросы:

---

### ❓ **1. Почему `declare(strict_types=1)` по умолчанию выключен?**

- **Обратная совместимость**: старые проекты и библиотеки часто зависят от нестрогой типизации, где `"123"` можно передать как `int`.
- Включение `strict_types` по умолчанию нарушило бы **миллионы существующих скриптов**.
- PHP позволяет **выбирать поведение** на уровне каждого файла — это гибко.

---

### ❓ **2. Чем `union` отличается от `mixed`?**

- `mixed` — **принимает всё что угодно**: `int`, `float`, `bool`, `array`, `object`, `null` и т. д. Это "что угодно".

```php
function handle(mixed $value) { ... }
```

- `union` — **строго ограничивает список допустимых типов**, например:

```php
function handle(int|float $value) { ... }
```


> ✅ `union` = безопаснее и точнее, чем `mixed`.

---

### ❓ **3. Зачем использовать `readonly`, если можно просто не менять свойство?**

- `readonly` — это **жёсткое ограничение на уровне интерпретатора**: попытка изменить значение вызовет `Error`.
- Это **документирует намерение**: "это значение устанавливается один раз и никогда не меняется".
- Полезно для **конфигураций, идентификаторов, слоёв DTO**, где изменение недопустимо.

```php
class Config {
    public readonly string $apiKey;
}
```

> ✅ Это не "психологическое" ограничение как `private`, это **физический запрет**.

---

### ❓ **4. Где удобно использовать `enum` в реальных проектах?**

- Статусы (`Draft`, `Published`, `Archived`)
- Типы пользователя (`Admin`, `Guest`, `Moderator`)
- Способы оплаты (`Card`, `Cash`, `PayPal`)
- Уровни доступа (`Read`, `Write`, `Full`)
- Типы событий (`Created`, `Updated`, `Deleted`)

> ✅ Это **альтернатива "магическим строкам"**, делает код **предсказуемым и IDE-дружелюбным**.

## 📌 Отличие `declare(strict_types=1)` от указания типов:

### `declare(strict_types=1)`

- **Влияет на приведение типов в аргументах функций и методах**, если тип указан.
- Пример без строгой типизации:

```php
function square(int $x): int {
	return $x * $x;
}

echo square("5"); // OK без declare(strict_types=1)
```

- Пример со строгой типизацией:

```php
declare(strict_types=1);

echo square("5"); // ❌ Fatal error: must be of the type int
```


🔹 **Область действия** — только **этот файл**.

---

### Указание типов (`int`, `string`, и т.д.)

- Это **аннотация типов**: PHP проверяет, что передаётся нужный тип.
- Работает как **во внутренних функциях**, так и в методах классов.
- Не гарантирует строгость **без `declare(strict_types=1)`**, потому что допускается автоматическое приведение.

---

### ⚙️ Как работает type hinting вне классов:

PHP позволяет **использовать типы в обычных (глобальных) функциях**:

```php
function greet(string $name): void {
    echo "Привет, $name!";
}

greet("Сергей"); // ✅
greet(123);      // ✅ без strict_types, ❌ с strict_types
```

Также можно использовать тайп-хинты для **анонимных функций**, `callback`, `array_map`, и т.д.

---

## 🔍 Кратко:

|Особенность|`declare(strict_types=1)`|`int`, `string`, `User` (тайп-хинты)|
|---|---|---|
|Проверяет тип строго|✅|❌ (если нет strict_types)|
|Влияет на передачу аргументов|✅|✅|
|Обязателен для строгой типизации|✅|Нужен вместе с тайпами|
|Работает только внутри файла|✅|Тайп-хинты работают везде|
