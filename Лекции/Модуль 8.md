### ⏱ 0:00–0:08 — **[SOLID за 7 минут](./Модуль%208%20подробно/SOLID%20за%207%20минут.md)** 

**Ключевые пункты:**

- **S — Single Responsibility Principle**  
    Каждый класс должен отвечать за одну вещь.  
    _Пример_: Класс `InvoicePrinter` должен печатать счёт, а не сохранять его в БД.
- **O — Open/Closed Principle**  
    Класс открыт для расширения, но закрыт для изменения.  
    _Пример_: Абстрактный класс `PaymentMethod` + реализации `Paypal`, `CreditCard`.
- **L — Liskov Substitution Principle**  
    Наследники должны быть взаимозаменяемыми.  
    _Пример_: Метод, принимающий `Bird`, должен работать с `Duck` и `Penguin` без ошибок.
- **I — Interface Segregation Principle**  
    Лучше много узких интерфейсов, чем один общий.  
    _Пример_: Не заставляй `Worker` реализовывать `IManager` с методом `fireEmployee()`.
- **D — Dependency Inversion Principle**  
    Зависимости от абстракций, а не от конкретных классов.  
    _Пример_: Зависимость от интерфейса `MailerInterface`, а не от `GmailMailer`.

### ⏱ 0:08–0:18 — **[MVC-поток](./Модуль%208%20подробно/MVC-поток.md)** 

**Ключевые пункты:** 
- **Front Controller:** одна точка входа (`index.php`)
- **Router:** определяет, какой контроллер вызывать
- **Controller:** логика обработки запроса
- **Model (если есть):** бизнес-логика и работа с БД
- **View:** отображение результата
- **Response:** возвращаем результат пользователю

**Интерактив:**  
Нарисуйте вместе с группой поток на доске/слайде:

```
Request
  ↓
[Front Controller]
  ↓
[Router]
  ↓
[Controller]
 ↙       ↘
Model    View
  ↓        ↓
Business   Template
Logic      Rendering
  ↓        ↓
      [Response]
```

### ⏱ 0:18–0:28 — **[DI и Service Container](./Модуль%208%20подробно/DI%20и%20Service%20Container.md)**  

**Ключевые пункты:** 
- **Dependency Injection:** передача зависимостей в класс через конструктор
- **Интерфейсы:** инверсия зависимости позволяет заменить реализацию
- **Service Container (Laravel):** умеет разрешать зависимости сам
- **Позднее связывание:** код не зависит от конкретной реализации до исполнения

**Интерактив:**  
Упражнение «Куда деть Logger?»  
Пример:

```php
class OrderService {
    public function __construct(LoggerInterface $logger) { ... }
}
```

Обсудите: где создать объект `Logger`? Ответ: пусть контейнер его создаёт и внедрит.

### ⏱ 0:28–0:38 — **[Распространённые паттерны](./Модуль%208%20подробно/Распространённые%20паттерны.md)**  

**Ключевые паттерны:** 
- **Factory Method**  
    Создание объектов через фабрику.  
    _Laravel пример_: `app()->make(SomeClass::class)`
- **Singleton**  
    Один экземпляр на приложение.  
    _Почему вреден:_ скрытые зависимости, трудно тестировать.
- **Repository**  
    Абстракция над доступом к данным.  
    _Laravel пример:_ `UserRepository` вместо прямого обращения к `User::where(...)`.
- **Strategy**  
    Переключаемое поведение.  
    _Пример:_ `PaymentStrategy` с `Paypal`, `Stripe` и т.д.
