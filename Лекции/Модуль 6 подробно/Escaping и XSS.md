
## **0:12–0:25 — Escaping и XSS**

---

### 🔹 **Цель блока:**

Показать студентам, что данные от пользователя — всегда потенциальная угроза, и объяснить, как защититься от XSS-атак с помощью экранирования и безопасных шаблонизаторов.

---

### 🔸 **Что такое XSS (Cross-Site Scripting)?**

**Определение:**

> XSS — это уязвимость, при которой злоумышленник внедряет JavaScript-код в веб-страницу, которая затем исполняется в браузере другого пользователя.

**Пример:**

```html
<script>alert('Взлом');</script>
```

Если сайт вставит это в HTML без экранирования — код выполнится в браузере.

---

### 🔸 **Типичный путь атаки:**

1. Пользователь вводит текст в поле формы (например, комментарий).
2. Этот текст сохраняется в базу без очистки.
3. Потом выводится в HTML:
```php
echo $_POST['comment'];
```
4. Если в поле был `<script>alert(1)</script>` — скрипт выполнится у всех, кто видит комментарий.

---

### 🔸 **Как защититься: экранирование (escaping)**

#### ✅ В PHP:

```php
echo htmlspecialchars($input, ENT_QUOTES, 'UTF-8');
```

- Превращает:
    - `<` → `&lt;` 
    - `>` → `&gt;` 
    - `"` → `&quot;` 
    - `'` → `&#039;` 
    - `&` → `&amp;` 

#### ✅ В Blade:

```blade
{{ $comment }}     // безопасно, экранируется автоматически
{!! $comment !!}   // НЕбезопасно — raw HTML
```

#### ✅ В Twig:

```twig
{{ comment }}  {# экранируется по умолчанию #}
{{ comment|raw }}  {# НЕбезопасно #}
```

---

### 🔸 **Контексты экранирования:**

XSS может проявиться в разных местах, и защита везде своя:

|Контекст|Пример|Метод защиты|
|---|---|---|
|Внутри HTML|`<div>{{ user.name }}</div>`|`htmlspecialchars()`|
|В HTML-атрибутах|`<a href="{{ url }}">`|`htmlspecialchars()`|
|В JS|`<script>let x = "{{ name }}";</script>`|JSON-encoding (`json_encode()`)|
|В URL|`<a href="/user?name={{ name }}">`|`urlencode()` / `rawurlencode()`|

---

### 🔸 **Особенности шаблонизаторов:**

|Шаблонизатор|Экранирует по умолчанию?|Ручное отключение экранирования|
|---|---|---|
|Blade|✅ Да|`{!! ... !!}`|
|Twig|✅ Да|`{{ var|
|Smarty|🚫 Нет (по умолчанию Off)|`{htmlspecialchars($var)}`|
|PHP-native|🚫 Нет|`htmlspecialchars()` вручную|

---

### 🧪 **Интерактивная демонстрация (XSS-демо):**

#### 💻 Пример без защиты:

```php
<?php
echo "Привет, " . $_GET['name'];
```

**URL:**

```
?name=<script>alert(1)</script>
```

**Результат:**  
Выполнится `alert(1)` — XSS уязвимость.

---

#### ✅ Пример с `htmlspecialchars`:

```php
<?php
echo "Привет, " . htmlspecialchars($_GET['name'], ENT_QUOTES, 'UTF-8');
```

**Результат:**  
Строка выведется как `&lt;script&gt;alert(1)&lt;/script&gt;`, ничего не выполнится.

---

#### 🔒 Пример в Blade:

```blade
Привет, {{ $name }}
```

Laravel сам экранирует, и XSS невозможен.
