
## ⏱️ 0:35–0:45 — **Лучшие практики: Front Controller, маршруты, конфиги**

### 🎯 Цель блока:

Показать, как правильно организовать начальную точку входа в приложение (файл `index.php`), подключение маршрутов и конфигураций. Это фундамент для масштабируемого и читаемого кода.

---

### 📌 Что не так с обычным подключением файлов?

Плохой пример:

```php
if ($_GET['page'] === 'about') {
    include 'about.php';
} elseif ($_GET['page'] === 'contacts') {
    include 'contacts.php';
} else {
    include 'home.php';
}
```

Недостатки:

- всё в одном месте;
- ручное управление URL-ами;
- дублирование логики;
- неудобно расширять.

---

## ✅ 1. **Front Controller (единая точка входа)**

### 📂 Идея:

У нас есть **один файл `index.php`**, который:

- запускается **всегда** (все запросы через него);
- загружает маршруты, конфиги, шаблоны;
- решает, **что и когда подключать**.

### 📁 Пример структуры:

```
project/
├── index.php
├── routes/
│   └── web.php
├── config/
│   ├── app.php
│   └── db.php
├── views/
│   ├── home.php
│   ├── about.php
│   └── layout/
│       ├── header.php
│       └── footer.php
```

---

### 🔧 `index.php` (пример)

```php
<?php

declare(strict_types=1);

// Устанавливаем часовой пояс и кодировку
date_default_timezone_set('Europe/Moscow');
mb_internal_encoding('UTF-8');

// Загружаем конфиги
$config = require __DIR__ . '/config/app.php';

// Подключаем маршруты
require __DIR__ . '/routes/web.php';
```

---

## ✅ 2. **Маршруты (`routes/web.php`)**

Простейшая ручная маршрутизация:

```php
$uri = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);

switch ($uri) {
    case '/about':
        require __DIR__ . '/../views/about.php';
        break;
    case '/':
    default:
        require __DIR__ . '/../views/home.php';
        break;
}
```

📌 Можно вынести в отдельную функцию `route($path)` или подключить сторонний роутер (например, `nikic/fast-route`).

---

## ✅ 3. **Конфиги (`config/*.php`)**

Пример: `config/app.php`

```php
<?php
return [
    'name' => 'My Site',
    'debug' => true,
    'timezone' => 'Europe/Moscow',
];
```

Подключаем:

```php
$config = require __DIR__ . '/../config/app.php';
```

Универсальная функция:

```php
function config(string $name): array {
    return require __DIR__ . "/../config/{$name}.php";
}
```

Тогда можно писать:

```php
$app = config('app');
echo $app['name'];
```

## 🔐 Дополнительно: защита от прямого доступа

### Проблема:

Что если кто-то напрямую откроет `views/about.php`?

### Решение:

1. Храним шаблоны в папке вне корня сайта.
2. Все запросы направляются в `index.php` через `.htaccess` или конфиг веб-сервера.

Для Apache:

```
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteRule ^ index.php [QSA,L]
```

---

## ✅ Резюме:

|Что мы делаем|Почему это хорошо|
|---|---|
|Используем `index.php` как роутер|Централизуем контроль, легче отлаживать|
|Разносим конфиги по `config/*.php`|Упрощаем настройку, разделяем ответственность|
|Подключаем маршруты через `web.php`|Читаемый и расширяемый способ управления страницами|
|Используем `__DIR__` + `require_once`|Надёжное подключение без повторений|

### ❓ **Почему плоха простая структура вида `about.php`, `contacts.php` и т.д.?**

#### 🔴 Проблема:

- Каждый файл — это **отдельная точка входа**.
- У каждого — **свой `header`, `footer`, конфиги, обработка ошибок`** (или их вообще нет).
- Нет единого места, где можно изменить поведение сайта.
- Сложно внедрить единый шаблон или оформление.

#### 🔧 Следствия:

- Дублирование кода (`<head>`, навигация, футер).
- Невозможность централизованно обрабатывать ошибки.
- Безопасность под вопросом — можно случайно выложить "лишний" PHP-файл наружу.

---

### ❓ **Что делать, если в проекте 50+ страниц?**

#### ✅ Решение:

1. **Front Controller** — один `index.php`, который обрабатывает все запросы.
2. **Роутинг** — файл `routes/web.php`, где на каждый путь (`/about`, `/news`, `/profile`) указано, какой view подключать.
3. **Шаблонизация** — шаблон layout + `include` для контента.
4. **Конфиги** — централизованные настройки в `config/*.php`.

#### 📌 Преимущества:

- Проект **масштабируется** без боли.
- Легко подключить систему шаблонов (Blade, Twig).
- Можно настроить логирование, кеш, БД в одном месте.

---

### ❓ **Как реализовать общую "шапку" и "подвал" для всех страниц?**

#### Стратегия:

1. Создаём `views/layout/header.php` и `footer.php`.
2. В каждом шаблоне `include` их с использованием `__DIR__`.

**Пример:**

```php
<?php include __DIR__ . '/layout/header.php'; ?>

<h1>О нас</h1>
<p>Мы работаем с 2005 года...</p>

<?php include __DIR__ . '/layout/footer.php'; ?>
```

📌 В дальнейшем можно:

- Обернуть это в отдельную функцию `view($template, $params)`;
- Перейти на шаблонизатор Blade, Twig или Plates.

### 🧩 Что такое **Front Controller**?

**Front Controller** — это **структурный шаблон проектирования**, который предусматривает **единую точку входа** для обработки всех HTTP-запросов.

---

### 📘 Формальное определение:

> **Front Controller** — это шаблон, при котором **все входящие запросы** к веб-приложению сначала обрабатываются **одним центральным контроллером**, который:
> 
> - выполняет начальную инициализацию (конфиги, подключение к БД, авторизацию и т.д.); 
> - анализирует запрос; 
> - делегирует выполнение нужному обработчику (view, controller, шаблону). 

---

### 💡 Примеры в PHP:

#### ❌ Без Front Controller:

```
/about.php
/contacts.php
/products.php
```

Каждый файл сам обрабатывает запрос. Нет централизованной логики. Прямой доступ к каждому из них.

#### ✅ С Front Controller:

```
/index.php
```

И весь входной трафик через:

```apacheconf
# .htaccess
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteRule ^ index.php [QSA,L]
```

Далее в `index.php`:

```php
// index.php
require __DIR__ . '/config/app.php';
require __DIR__ . '/routes/web.php';
dispatch($_SERVER['REQUEST_URI']);
```

---

### 🧠 Зачем использовать этот шаблон:

|Без Front Controller|С Front Controller|
|---|---|
|Много входных точек|Одна входная точка (`index.php`)|
|Распылённая логика|Централизованная логика|
|Трудно отлаживать|Проще вести журнал, ставить точки останова|
|Невозможно глобальное поведение|Легко внедрить middleware (аутентификация, логирование)|

---

### 📌 Где используется Front Controller?

- ✅ Все современные PHP-фреймворки:
    - Laravel → `public/index.php`
    - Symfony → `public/index.php`
    - Yii → `index.php`

- ✅ Практически все MVC-фреймворки и SPA-бекенды.

### 🧷 Как это объяснить студенту просто:

> Вместо того чтобы в каждый файл вставлять настройки, базу и шаблоны — делаем **один стартовый файл**, через который проходит всё. Он как турникет: сначала всё туда, а потом уже по назначению.
