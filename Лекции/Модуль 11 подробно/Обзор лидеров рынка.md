
## 📦 Блок 3 — **Обзор лидеров СУБД (0:22–0:30)**

---

### 🎯 Цель блока:

- Познакомить с конкретными системами управления базами данных, которые чаще всего используются в вебе и смежных областях.
- Понять, **почему и где их применяют**.
- Объяснить выбор MySQL как «дефолта» для веба.

---

### 🏆 Основные игроки рынка:

---

### 1. **MySQL / MariaDB**

- **MySQL** — одна из самых популярных СУБД для веб-приложений.
- Открытый код, но принадлежит Oracle.
- **MariaDB** — форк MySQL, созданный из-за опасений коммерциализации.
- Простота установки, низкий порог входа.
- Хорошая производительность для классических сайтов.
- Широкая поддержка в CMS: WordPress, Joomla, Bitrix.

🔹 **Где применяют**:

- Корпоративные сайты.
- Интернет-магазины.
- SaaS-продукты.

---

### 2. **PostgreSQL**

- Сильная альтернатива MySQL.
- Более строгий подход к стандарту SQL.
- Поддержка сложных запросов, JSON, Full-text search.
- Используется там, где важна надёжность и сложная логика данных.

🔹 **Где применяют**:

- Финансовые системы.
- Геоинформационные сервисы (PostGIS).
- Веб-приложения с нестандартной логикой.

---

### 3. **SQLite**

- Миниатюрная реляционная СУБД.
- Хранит всю базу в **одном файле**.
- Не требует отдельного сервера.
- Используется в мобильных приложениях, браузерах, тестовых средах.

🔹 **Где применяют**:

- Приложения на смартфонах.
- Локальное хранение данных.
- Встраиваемые решения (IoT).

---

### 4. **MongoDB**

- Документо-ориентированная СУБД.
- Гибкая схема (или вовсе её отсутствие).
- Удобна для быстрого старта и прототипирования.
- Высокая горизонтальная масштабируемость.

🔹 **Где применяют**:

- Каталоги с динамической структурой.
- Логирование, хранение событий.
- Реализация backend для мобильных приложений.

---

### 5. **Redis**

- In-memory key-value store.
- Очень быстрый доступ к данным.
- Поддерживает структуры данных: списки, множества, хэши.
- Используется как кэш, брокер сообщений, счётчик.

🔹 **Где применяют**:

- Кэширование сессий.
- Реализация очередей.
- Pub/Sub системы.

---

### 6. **ElasticSearch**

- Поисковый движок, но используется как NoSQL БД.
- Отлично справляется с полнотекстовым поиском.
- Поддерживает агрегаты, фильтрацию, сложные запросы.

🔹 **Где применяют**:

- Поиск по сайту.
- Логирование и мониторинг (в связке с Logstash, Kibana).
- Big Data search.

---

### 📊 Сводная таблица:

|СУБД|Тип|Сильные стороны|Типичные задачи|
|---|---|---|---|
|MySQL / MariaDB|Реляционная|Простота, поддержка CMS|Веб-сайты, SaaS|
|PostgreSQL|Реляционная|Надёжность, сложные запросы|Финансы, GIS|
|SQLite|Реляционная|Локальное хранение, file-based|Мобильные приложения|
|MongoDB|Документо-ориентированная|Гибкость, масштабирование|Каталоги, JSON-данные|
|Redis|Key-Value|Скорость, in-memory|Кэш, очереди|
|ElasticSearch|Документо-ориентированная|Полнотекстовый поиск|Поиск, аналитика|

---

### 💬 Вопросы аудитории:

- Почему Redis нельзя использовать как основную БД для сайта?
- Когда лучше выбрать PostgreSQL вместо MySQL?
- Почему SQLite хорош для мобильных приложений, но не для продакшн сайта?

---

### 📝 Итог блока:

- Веб-разработчики чаще всего работают с MySQL, PostgreSQL, MongoDB.
- Redis и ElasticSearch — это специализированные решения, дополняющие основные СУБД.
- SQLite — идеален для мобильных решений.
- Нет «лучшей» базы — всё зависит от задачи.

---

### ✅ Результат для студента:

- Умеет быстро ориентироваться в популярных СУБД.
- Понимает, зачем каждая из них используется.
- Может выбрать правильный инструмент под задачу.
