## 🧱 Что такое DDL?

- DDL — язык **определения структуры данных** в SQL.
- Меняет **схему базы данных** (таблицы, индексы, ограничения).
- Основные команды:
    - `CREATE`  
    - `ALTER`  
    - `DROP`  

⚠️ **Важно**: DDL-команды меняют структуру БД и часто необратимы (удаление таблицы с данными).

---

## 🏗️ Основные команды DDL

### 1. **CREATE DATABASE**

- Создаёт новую базу данных.

```sql
CREATE DATABASE my_app;
```

### 2. **CREATE TABLE**

- Создаёт новую таблицу со столбцами и их типами.

```sql
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE,
    age INT CHECK (age >= 18)
);
```

### Объяснение:

- `id` — первичный ключ с автоинкрементом.
- `name` — не может быть NULL.
- `email` — уникальный (не может быть повторов).
- `age` — должен быть >= 18 (ограничение CHECK).

---

### 3. **ALTER TABLE**

- Изменяет уже существующую таблицу.

#### Добавление колонки:

```sql
ALTER TABLE users ADD COLUMN phone VARCHAR(20);
```

#### Изменение типа колонки:

```sql
ALTER TABLE users MODIFY COLUMN name VARCHAR(150);
```

#### Удаление колонки:

```sql
ALTER TABLE users DROP COLUMN phone;
```

#### Добавление ограничения:

```sql
ALTER TABLE users ADD CONSTRAINT chk_age CHECK (age >= 18);
```

---

### 4. **DROP TABLE**

- Удаляет таблицу полностью.

```sql
DROP TABLE users;
```

⚠️ Все данные таблицы будут удалены без возможности восстановления.

---

## 🛡️ Ограничения (Constraints)

### 1. **NOT NULL**

- Колонка обязательно должна иметь значение.
- Гарантирует, что поле заполнено.

```sql
name VARCHAR(100) NOT NULL
```

### 2. **UNIQUE**

- Значение колонки должно быть уникальным среди всех строк.
- Полезно для email, логинов и т.д.

```sql
email VARCHAR(255) UNIQUE
```

### 3. **CHECK**

- Позволяет задавать логические условия для значений.
- Например, ограничить возраст.

```sql
age INT CHECK (age >= 18)
```

⚠️ В MySQL до версии 8.0 CHECK игнорировался — важно помнить!

### 4. **PRIMARY KEY**

- Уникальный идентификатор строки.
- Часто используется вместе с AUTO_INCREMENT.

### 5. **FOREIGN KEY**

- Устанавливает связь с другой таблицей.

```sql
FOREIGN KEY (user_id) REFERENCES users(id)
```

## 📝 Пример реального кейса:

Хотим добавить в таблицу `orders` колонку `status`, которая может быть только 'new', 'processing', 'completed':

```sql
ALTER TABLE orders ADD COLUMN status VARCHAR(20) CHECK (status IN ('new', 'processing', 'completed'));
```

Отвечаю на ваши вопросы в контексте MySQL:

### 1. Почему UNIQUE предпочтительнее для email, чем просто индекс?

UNIQUE индекс предпочтительнее для email, потому что:
- Гарантирует уникальность значений: нельзя вставить два одинаковых email
- Одновременно обеспечивает быстрый поиск (как обычный индекс)
- Позволяет избежать дубликатов данных, что критично для таких полей как email
- Может использоваться как внешний ключ (FOREIGN KEY)
- Автоматически создаёт индекс, поэтому не нужно создавать дополнительный обычный индекс

Пример:
```sql
CREATE TABLE users (
    email VARCHAR(255) UNIQUE
);
-- Лучше чем:
CREATE TABLE users (
    email VARCHAR(255),
    INDEX (email)
);
```

### 2. Чем отличается DROP TABLE от DELETE FROM?

Основные различия:

| DROP TABLE | DELETE FROM |
|------------|-------------|
| Удаляет всю таблицу вместе со структурой | Удаляет только данные, оставляя структуру таблицы |
| Освобождает место в БД | Обычно не освобождает место (для InnoDB) |
| Требует прав на DDL операции | Требует прав на DML операции |
| Автоматически коммитит транзакцию | Может быть частью транзакции |
| Нельзя использовать с WHERE | Можно использовать с WHERE для выборочного удаления |
| Быстрее для удаления всех данных | Медленнее для больших таблиц |

Примеры:
```sql
-- Удаляет таблицу полностью
DROP TABLE users;

-- Удаляет все строки из таблицы (но сама таблица остаётся)
DELETE FROM users;

-- Удаляет только определённые строки
DELETE FROM users WHERE id > 100;
```

### 3. Когда и зачем использовать CHECK-ограничения?

CHECK-ограничения в MySQL (начиная с версии 8.0.16) используются для:
- Обеспечения целостности данных на уровне БД
- Проверки значений перед вставкой или обновлением
- Реализации бизнес-правил прямо в схеме БД

Типичные случаи использования:
1. Проверка диапазонов значений:
```sql
CREATE TABLE products (
    price DECIMAL(10,2) CHECK (price > 0)
);
```

2. Проверка формата данных:
```sql
CREATE TABLE users (
    age INT CHECK (age >= 18 AND age <= 120)
);
```

3. Сложные условия между полями:
```sql
CREATE TABLE orders (
    order_date DATE,
    delivery_date DATE,
    CHECK (delivery_date >= order_date)
);
```

4. Проверка по регулярному выражению (MySQL 8.0+):
```sql
CREATE TABLE contacts (
    phone VARCHAR(20) CHECK (phone REGEXP '^[0-9]{10}$')
);
```

Преимущества CHECK-ограничений:
- Перенос логики валидации на уровень БД
- Единообразие проверок для всех приложений, работающих с БД
- Предотвращение некорректных данных на самом низком уровне
- Упрощение кода приложения

Примечание: В версиях MySQL до 8.0.16 CHECK-ограничения синтаксически поддерживались, но игнорировались.
