## 📦 Модуль 11 — «От файла к СУБД. Почему MySQL — default для веба»

### 🕐 1-й академический час (45 минут)

---

### **0:00–0:12 — [Эволюция хранения данных](./Модуль%2011%20подробно/Эволюция%20хранения%20данных.md)**

1. **Файлы** — простейшее хранение (txt, csv). Нет индексов, поиска, транзакций.
2. **CSV** — полуформализованный формат для обмена табличными данными.
3. **DBM (Database Manager)** — простые key-value базы (Berkeley DB, GDBM).
4. **RDBMS (Relational DBMS)** — основа корпоративных приложений. SQL, связи, индексы, транзакции.
5. **NoSQL** — масштабирование, гибкие схемы (MongoDB, Redis). BASE вместо ACID.
6. **NewSQL** — гибкость NoSQL + строгая консистентность (CockroachDB, TiDB).
7. **ACID**: Atomicity, Consistency, Isolation, Durability.
8. **BASE**: Basically Available, Soft state, Eventual consistency.

> 💡 **Вопрос аудитории**: Почему NoSQL так популярен для больших проектов?

---

### **0:12–0:22 — [Классификация СУБД](./Модуль%2011%20подробно/Классификация%20СУБД.md)**

1. **Реляционные** — таблицы, связи, SQL (MySQL, PostgreSQL).
2. **Документо-ориентированные** — хранение JSON-документов (MongoDB).
3. **Колонко-ориентированные** — быстрые агрегации по столбцам (ClickHouse, Cassandra).
4. **Графовые** — связи между сущностями (Neo4j).
5. **Time-series** — данные по времени (InfluxDB, TimescaleDB).

### **0:22–0:30 — [Обзор лидеров рынка](./Модуль%2011%20подробно/Обзор%20лидеров%20рынка.md)**

|СУБД|Где применяют|
|---|---|
|**MySQL/MariaDB**|классические веб-приложения, CMS|
|**PostgreSQL**|сложные аналитические проекты, GIS|
|**SQLite**|мобильные приложения, тестовые среды|
|**MongoDB**|быстрый прототипинг, документы|
|**Redis**|кэширование, pub/sub, очереди|
|**ElasticSearch**|полнотекстовый поиск|

> 💡 **Вопрос аудитории**: Почему SQLite так популярен в мобильных приложениях?

---

### **0:30–0:45 — [MySQL в деталях](./Модуль%2011%20подробно/MySQL%20в%20деталях.md)**

1. **Editions** — Community (бесплатно) vs Enterprise (расширенные возможности).
2. **Storage Engines** — InnoDB (по умолчанию), MyISAM (устарел), MEMORY, CSV.
3. **InnoDB**:
    - поддержка транзакций (ACID),
    - внешние ключи,
    - row-level locking.
4. **MyISAM**:
    - быстрее на чтение,
    - не поддерживает транзакции.
5. **JSON-тип** — хранение полуструктурированных данных.
6. **CTE (WITH ... AS)** — рекурсивные запросы.
7. **Window Functions** — агрегаты по "окнам" строк.

### **0:50–1:05 — [Установка и запуск MySQL](./Модуль%2011%20подробно/Установка%20и%20запуск%20MySQL.md)**

1. **Docker-compose**:

```yaml
services:
mysql:
image: mysql:8.2
environment:
  MYSQL_ROOT_PASSWORD: secret
ports:
  - "3306:3306"
```

2. **Клиенты**:

- CLI: `mysql -u root -p`,
- GUI: MySQL Workbench, DBeaver.

2. **Мини-демо**:

```bash
docker exec -it <container_name> bash
mysql -u root -p
SELECT VERSION();
```

---

### **1:05–1:20 — [Основы SQL-моделирования](./Модуль%2011%20подробно/Основы%20SQL-моделирования.md)**

1. **database → table → row** — структура хранения.
2. **Типы данных**:
    - INT, BIGINT,
    - VARCHAR(n), TEXT,
    - DATETIME, DATE,
    - JSON.
3. **Первичный ключ (PRIMARY KEY)** — уникальный идентификатор строки.
4. **Внешний ключ (FOREIGN KEY)** — связь между таблицами.
5. **Индексы (INDEX)** — ускоряют поиск и сортировку.

### **1:20–1:35 — [DDL-команды](./Модуль%2011%20подробно/DDL-команды.md)**

1. **CREATE DATABASE test;**  
2. **CREATE TABLE users (id INT PRIMARY KEY, name VARCHAR(100));**  
3. **ALTER TABLE users ADD COLUMN email VARCHAR(100);**  
4. **DROP TABLE users;**  
5. **Ограничения**:
    - NOT NULL,
    - UNIQUE,

### **1:35–1:45 — Mini-live: [создаём БД tasks](./Модуль%2011%20подробно/создаём%20БД%20tasks.md)**

1. **Создание БД**:  

```sql
CREATE DATABASE tasks;
USE tasks;
```

2. **Создание таблицы users**:  

```sql
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE
);
```

3. **CLI команды**:  

```bash
mysql -u root -p tasks
SHOW TABLES;
DESCRIBE users;
```
