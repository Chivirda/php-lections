# Эволюция бэкенда

### ✅ **CGI (Common Gateway Interface)**

**Что это такое:**
CGI — это первый стандарт взаимодействия веб-сервера с программами, которые обрабатывают запросы. Появился в 1993 году.

**Как работает:**
1. Пользователь делает запрос (например, к `form.cgi`).
2. Веб-сервер **создаёт отдельный процесс** операционной системы для этой программы (например, на Perl или C).
3. Программа получает данные запроса (через переменные среды и stdin).
4. Возвращает HTTP-ответ через stdout.
5. Сервер отдаёт ответ пользователю.

**Плюсы:**
- Простота: можно написать любой скрипт на любом языке.
- Гибкость.

**Минусы:**
- Очень медленно: **на каждый запрос создаётся отдельный процесс**. Представь себе 1000 одновременных пользователей — 1000 процессов.
- Большая нагрузка на CPU и память.

---

### ✅ **FastCGI**

**Что это такое:**
FastCGI — улучшенная версия CGI. Основное отличие: **процесс создаётся один раз и работает постоянно**, обслуживая множество запросов.

**Как работает:**
1. Один или несколько процессов FastCGI стартуют отдельно.
2. Веб-сервер (например, Nginx) передаёт запросы этим процессам через сокеты.
3. FastCGI-процесс обрабатывает запрос и возвращает ответ, **не завершаясь**.

**Плюсы:**
- Существенно быстрее CGI (нет постоянного создания процессов).
- Разделение логики приложения и веб-сервера (можно писать на PHP, Python, даже Java).

**Пример:**  
PHP с Nginx почти всегда работает через PHP-FPM (FastCGI Process Manager).

---

### ✅ **WSGI / PSGI**

**Что это такое:**
- **WSGI (Web Server Gateway Interface)** — стандарт взаимодействия веб-серверов и Python-приложений.
- **PSGI** — его аналог в мире Perl.

**Зачем нужны:**
- Устанавливают **единый способ, как веб-приложение получает запрос и возвращает ответ**.
- Благодаря WSGI можно запускать Python-приложения на любом сервере (uWSGI, Gunicorn, mod_wsgi и т.д.).

**Пример (Python):**
```python
def application(environ, start_response):
    start_response('200 OK', [('Content-Type', 'text/plain')])
    return [b'Hello, World!']
```

**Плюсы:**
- Гибкость и модульность.
- Поддержка middleware (можно оборачивать функции для логирования, кэширования и пр.).

---

### ✅ **Концепция `request → обработка → response`**

Это **базовая модель** любой серверной системы, начиная с CGI и до современных фреймворков вроде Laravel, Django или Express.js.

**Как это выглядит:**
1. Клиент (браузер) отправляет **HTTP-запрос**.
2. Сервер **принимает и разбирает запрос** (метод, путь, заголовки, тело).
3. Запрос **передаётся приложению**, где выбирается логика обработки (маршруты, контроллеры, бизнес-логика).
4. Формируется **HTTP-ответ**: статус, заголовки, тело.
5. Ответ **отправляется клиенту**.

**Пример — что делает фреймворк:**
```plaintext
[Request: GET /user/42]
→ роутинг → контроллер → доступ к БД → формирование ответа
→ [Response: 200 OK + JSON]
```

Эта модель используется **в любом серверном языке и фреймворке**. Это как “основной цикл жизни запроса”.

# Обзор популярных языков

Конечно, давай подробно разберём обзор популярных языков для бэкенда и **как выбирать язык под конкретные задачи**.

---

## 🔍 **1. Обзор языков**

### 🐘 PHP  
- **Низкий порог входа**: легко начать, много туториалов, работает «из коробки».
- **Огромная база готовых решений**: WordPress, Joomla, OpenCart.
- **Фреймворки**: Laravel, Symfony, Yii.
- **Где используется**: сайты, блоги, интернет-магазины, панели управления, API.

---

### ⚡ Node.js  
- **JavaScript на сервере** — один язык на фронте и бэке.
- **Асинхронность** по умолчанию — хорош для real-time (чаты, WebSocket, игры).
- **Экосистема NPM** — огромная база пакетов.
- **Где используется**: real-time приложения, REST API, SPA backend, микросервисы.

---

### 🐍 Python  
- **Читаемость и простота** — легко читать, писать, поддерживать.
- **Сильные стороны**: научные библиотеки, ML, парсинг, автоматизация.
- **Фреймворки**: Django, Flask, FastAPI.
- **Где используется**: веб-приложения, API, админки, скрипты, стартапы.

---

### 💎 Ruby  
- **Философия “разработка с удовольствием”**.
- **Ruby on Rails** — один из первых мощных фреймворков.
- **Минусы**: менее популярен сейчас, сложнее найти разработчиков.
- **Где используется**: быстрые MVP, стартапы, SaaS-платформы.

---

### ☕ Java / Kotlin  
- **Java** — классика: стабильность, масштабируемость, зрелая экосистема.
- **Kotlin** — современная замена Java, лаконичный синтаксис.
- **Фреймворки**: Spring Boot, Micronaut, Ktor.
- **Где используется**: банки, госы, корпорации, Android, высоконагруженные системы.

---

### 🧩 C# / .NET  
- **Интеграция с Windows** и корпоративной средой.
- **.NET Core** теперь кроссплатформенный.
- **Хорошие инструменты от Microsoft**.
- **Где используется**: корпоративные CRM, ERP, десктопные приложения, сайты на ASP.NET.

---

### 🦫 Go и 🦀 Rust  
- **Go (Golang)**: простота, высокая скорость, хорошие возможности параллельности.
- **Rust**: высокая безопасность, контроль над памятью, сложнее в изучении.
- **Где используются**: микросервисы, backend-инфраструктура, инструменты CLI, системы с высоким трафиком.

# Стек и инфраструктура

## 📦 Что такое стек?

**Стек технологий** — это набор компонентов, которые совместно обеспечивают работу веб-приложения:
- ОС сервера
- Веб-сервер
- Язык программирования
- База данных
- Клиентская часть

---

## 🔹 **LAMP** — классика веба

> **L**inux, **A**pache, **M**ySQL, **P**HP

- **Linux** — операционная система сервера.
- **Apache** — веб-сервер, обслуживает HTTP-запросы.
- **MySQL** — реляционная база данных.
- **PHP** — серверный язык, обрабатывает бизнес-логику.

**Где используется:**  
WordPress, Joomla, Drupal, множество старых и новых проектов.

**Плюсы:**
- Простота настройки.
- Проверенное временем решение.
- Доступность на любом хостинге.

---

## 🔸 **LEMP** — современная альтернатива

> **L**inux, **E**ngineX (читается "engine x"), **M**ySQL, **P**HP

- Отличие в веб-сервере: **Nginx** вместо Apache.
- Nginx — более быстрый, лучше работает с нагрузкой, эффективен в проксировании.

**Где используется:**  
Современные сайты на Laravel, Symfony, WordPress.

---

## 🟢 **MEAN** — JavaScript во всём

> **M**ongoDB, **E**xpress, **A**ngular, **N**ode.js

- **MongoDB** — NoSQL база данных.
- **Express** — минималистичный фреймворк для Node.js.
- **Angular** — фреймворк для фронтенда от Google.
- **Node.js** — серверная среда исполнения JavaScript.

**Где используется:**  
SPA-приложения, real-time проекты, стартапы.

**Особенность:**  
Всё пишется на **одном языке — JavaScript**, и на фронте, и на бэке.

---

## 🟡 **JAMStack** — новая школа

> **J**avaScript, **A**PIs, **M**arkup

- Фронтенд собирается как **статический HTML**, часто через генераторы (Next.js, Gatsby, Hugo).
- Данные подгружаются через API.
- Хостинг: Netlify, Vercel, GitHub Pages.

**Где используется:**  
Блоги, маркетинговые лендинги, документация, малые и быстрые сайты.

**Преимущества:**
- Мгновенная загрузка.
- Максимальная безопасность (нет сервера = нечему ломаться).
- Простота масштабирования.

---

## ☁️ **Serverless** — без серверов?

> Не значит, что «вообще без сервера», а **без необходимости управлять им вручную**.

Пример: **AWS Lambda**, **Google Cloud Functions**, **Yandex Cloud Functions**.

**Как это работает:**
- Вы пишете только **функцию** (например, `handleRequest()`).
- Клауд-сервис сам запускает её при запросе, масштабирует и завершает.

**Где используется:**  
Webhook-и, API, ивенты, Telegram-боты, задачи по расписанию.

**Плюсы:**
- Оплата только за фактическое использование.
- Нет заботы о сервере и его конфигурации.
- Масштабируемость "из коробки".

## 📌 Итог

- Стек — это каркас вашего приложения.
- LAMP/LEMP — отличны для традиционных сайтов.
- MEAN — удобен, если любишь JavaScript.
- JAMStack и Serverless — тренды для быстрого, безопасного и масштабируемого фронта.
