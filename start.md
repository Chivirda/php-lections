# Эволюция бэкенда

### ✅ **CGI (Common Gateway Interface)**

**Что это такое:**
CGI — это первый стандарт взаимодействия веб-сервера с программами, которые обрабатывают запросы. Появился в 1993 году.

**Как работает:**
1. Пользователь делает запрос (например, к `form.cgi`).
2. Веб-сервер **создаёт отдельный процесс** операционной системы для этой программы (например, на Perl или C).
3. Программа получает данные запроса (через переменные среды и stdin).
4. Возвращает HTTP-ответ через stdout.
5. Сервер отдаёт ответ пользователю.

**Плюсы:**
- Простота: можно написать любой скрипт на любом языке.
- Гибкость.

**Минусы:**
- Очень медленно: **на каждый запрос создаётся отдельный процесс**. Представь себе 1000 одновременных пользователей — 1000 процессов.
- Большая нагрузка на CPU и память.

---

### ✅ **FastCGI**

**Что это такое:**
FastCGI — улучшенная версия CGI. Основное отличие: **процесс создаётся один раз и работает постоянно**, обслуживая множество запросов.

**Как работает:**
1. Один или несколько процессов FastCGI стартуют отдельно.
2. Веб-сервер (например, Nginx) передаёт запросы этим процессам через сокеты.
3. FastCGI-процесс обрабатывает запрос и возвращает ответ, **не завершаясь**.

**Плюсы:**
- Существенно быстрее CGI (нет постоянного создания процессов).
- Разделение логики приложения и веб-сервера (можно писать на PHP, Python, даже Java).

**Пример:**  
PHP с Nginx почти всегда работает через PHP-FPM (FastCGI Process Manager).

---

### ✅ **WSGI / PSGI**

**Что это такое:**
- **WSGI (Web Server Gateway Interface)** — стандарт взаимодействия веб-серверов и Python-приложений.
- **PSGI** — его аналог в мире Perl.

**Зачем нужны:**
- Устанавливают **единый способ, как веб-приложение получает запрос и возвращает ответ**.
- Благодаря WSGI можно запускать Python-приложения на любом сервере (uWSGI, Gunicorn, mod_wsgi и т.д.).

**Пример (Python):**
```python
def application(environ, start_response):
    start_response('200 OK', [('Content-Type', 'text/plain')])
    return [b'Hello, World!']
```

**Плюсы:**
- Гибкость и модульность.
- Поддержка middleware (можно оборачивать функции для логирования, кэширования и пр.).

---

### ✅ **Концепция `request → обработка → response`**

Это **базовая модель** любой серверной системы, начиная с CGI и до современных фреймворков вроде Laravel, Django или Express.js.

**Как это выглядит:**
1. Клиент (браузер) отправляет **HTTP-запрос**.
2. Сервер **принимает и разбирает запрос** (метод, путь, заголовки, тело).
3. Запрос **передаётся приложению**, где выбирается логика обработки (маршруты, контроллеры, бизнес-логика).
4. Формируется **HTTP-ответ**: статус, заголовки, тело.
5. Ответ **отправляется клиенту**.

**Пример — что делает фреймворк:**
```plaintext
[Request: GET /user/42]
→ роутинг → контроллер → доступ к БД → формирование ответа
→ [Response: 200 OK + JSON]
```
---

Эта модель используется **в любом серверном языке и фреймворке**. Это как “основной цикл жизни запроса”.

# Стек и инфраструктура

## 📦 Что такое стек?

**Стек технологий** — это набор компонентов, которые совместно обеспечивают работу веб-приложения:
- ОС сервера
- Веб-сервер
- Язык программирования
- База данных
- Клиентская часть

---

## 🔹 **LAMP** — классика веба

> **L**inux, **A**pache, **M**ySQL, **P**HP

- **Linux** — операционная система сервера.
- **Apache** — веб-сервер, обслуживает HTTP-запросы.
- **MySQL** — реляционная база данных.
- **PHP** — серверный язык, обрабатывает бизнес-логику.

**Где используется:**  
WordPress, Joomla, Drupal, множество старых и новых проектов.

**Плюсы:**
- Простота настройки.
- Проверенное временем решение.
- Доступность на любом хостинге.

---

## 🔸 **LEMP** — современная альтернатива

> **L**inux, **E**ngineX (читается "engine x"), **M**ySQL, **P**HP

- Отличие в веб-сервере: **Nginx** вместо Apache.
- Nginx — более быстрый, лучше работает с нагрузкой, эффективен в проксировании.

**Где используется:**  
Современные сайты на Laravel, Symfony, WordPress.

---

## 🟢 **MEAN** — JavaScript во всём

> **M**ongoDB, **E**xpress, **A**ngular, **N**ode.js

- **MongoDB** — NoSQL база данных.
- **Express** — минималистичный фреймворк для Node.js.
- **Angular** — фреймворк для фронтенда от Google.
- **Node.js** — серверная среда исполнения JavaScript.

**Где используется:**  
SPA-приложения, real-time проекты, стартапы.

**Особенность:**  
Всё пишется на **одном языке — JavaScript**, и на фронте, и на бэке.

---

## 🟡 **JAMStack** — новая школа

> **J**avaScript, **A**PIs, **M**arkup

- Фронтенд собирается как **статический HTML**, часто через генераторы (Next.js, Gatsby, Hugo).
- Данные подгружаются через API.
- Хостинг: Netlify, Vercel, GitHub Pages.

**Где используется:**  
Блоги, маркетинговые лендинги, документация, малые и быстрые сайты.

**Преимущества:**
- Мгновенная загрузка.
- Максимальная безопасность (нет сервера = нечему ломаться).
- Простота масштабирования.

---

## ☁️ **Serverless** — без серверов?

> Не значит, что «вообще без сервера», а **без необходимости управлять им вручную**.

Пример: **AWS Lambda**, **Google Cloud Functions**, **Yandex Cloud Functions**.

**Как это работает:**
- Вы пишете только **функцию** (например, `handleRequest()`).
- Клауд-сервис сам запускает её при запросе, масштабирует и завершает.

**Где используется:**  
Webhook-и, API, ивенты, Telegram-боты, задачи по расписанию.

**Плюсы:**
- Оплата только за фактическое использование.
- Нет заботы о сервере и его конфигурации.
- Масштабируемость "из коробки".

## 🔧 Актуальная версия — **PHP 8.3**

### Что нового в 8.3 (по состоянию на 2024–2025):

> 📌 Суть: развитие идёт в сторону строгости и безопасности, но при этом язык сохраняет простоту.

## 🚀 JIT-компиляция и OPcache

### Что это такое:
- **OPcache** — кэширует скомпилированный байткод PHP, ускоряет повторный запуск.
- **JIT (Just-In-Time Compilation)** — с PHP 8.0: позволяет часть PHP-кода компилировать в машинный код на лету.

### Польза:
- **Быстрее** работает числовая математика, рекурсивные функции, генераторы.
- **Реальный выигрыш** — в проектах с тяжёлой логикой или при высоких нагрузках.

> 💬 Миф: «PHP медленный» — с OPcache и JIT это уже **давно не так**.

# Сильные стороны PHP

---

## 🔹 Простота деплоя

**Что это значит:**
- PHP — это **интерпретируемый язык**, который **работает сразу**, без компиляции.
- **Многие хостинги** (особенно shared-hosting, т.е. дешёвые виртуальные хостинги) **уже имеют поддержку PHP** по умолчанию.
- Чтобы задеплоить сайт на PHP, достаточно:
  1. Закинуть `.php` файлы на сервер (через FTP, SFTP, панель управления).
  2. Убедиться, что сервер поддерживает Apache или Nginx с PHP.
  3. Готово — сайт работает.

**Пример:**
```php
<?php echo "Привет, мир!"; ?>
```
Этот файл можно просто скопировать на сервер, и он будет работать.

🔧 *На других языках (например, Java, Node.js) нужно отдельно поднимать окружение, управлять зависимостями, запускать процессы.*

# Слабые стороны и мифы

---

## 🔻 Миф 1: «PHP — это медленно»

### Почему этот миф появился:
- Исторически, **PHP 4 и 5** действительно работали медленно по сравнению с Java или C++.
- Не было компиляции, всё интерпретировалось на каждый запрос.
- Разработка часто велась без кэширования, с копипастой кода и тяжёлыми циклами.

### Что изменилось:

#### ✅ **OPcache (с PHP 5.5+)**
- Это встроенный механизм, который **кэширует байткод PHP-файлов**, чтобы не компилировать их заново при каждом запросе.
- Значительно ускоряет запуск приложений.
- Включается одной строкой в `php.ini`:
  ```ini
  opcache.enable=1
  ```

#### ✅ **JIT (Just-in-Time Compiler) — с PHP 8.0**
- Позволяет PHP-коду компилироваться в машинный код во время выполнения.
- Особо эффективен в вычислительно тяжёлых задачах: циклы, математика, рекурсия.
- Примерно на **10–30%** быстрее в типовых кейсах.
- Можно настроить уровень агрессии JIT:
  ```ini
  opcache.jit=1255
  ```

📌 **Вывод:** сегодня PHP работает **достаточно быстро**, особенно для задач типа CRUD/API.

---

## 🔻 Миф 2: «PHP — это спагетти-код»

### Что такое спагетти-код:
- Перемешанный HTML и PHP в одном файле.
- Копипаста без функций и классов.
- Нет архитектуры, логики, шаблонов.

### Почему этот миф появился:
- В 2000–2010 годах многие создавали сайты на PHP без опыта.
- Были популярны CMS с грязным кодом: старые версии Joomla, WordPress, самописки.
- Сам язык не имел строгих требований (до PHP 7 даже типизация была формальной).

### Что изменилось:

#### ✅ Современные фреймворки (Laravel, Symfony)
- Жёсткое разделение логики: MVC (Model–View–Controller).
- Использование шаблонизаторов (Blade, Twig).
- Контейнер зависимостей, миграции, роутинг, тестирование.

#### ✅ Composer и автозагрузка
- Composer — как npm или pip: чёткая структура и зависимости.
- PSR-4 автозагрузка классов:
  ```json
  "autoload": {
      "psr-4": {
          "App\\": "app/"
      }
  }
  ```

#### ✅ PSR — PHP Standard Recommendations
- **PSR-1, PSR-2, PSR-12** — стандарты форматирования и стиля кода.
- **PSR-4** — стандарт автозагрузки.
- **PSR-7** — стандартизированный HTTP-запрос и ответ.
- **PSR-11** — контейнер зависимостей.

📌 **Вывод:** спагетти-код — не проблема языка, а подхода. Современный PHP-код может быть **чистым, читаемым и строго структурированным**.

---

## 🔻 Другие предрассудки

### ❌ «PHP — устаревший язык»
- Реальность: **язык активно развивается**, каждая новая версия приносит улучшения.
- В PHP 8+: named arguments, union types, match expression, JIT.

### ❌ «На PHP не делают серьёзные проекты»
- Примеры:
  - **Facebook** начинался на PHP (сейчас работает через HHVM, но корень в PHP).
  - **Wikipedia**, **Slack (частично)**, **Mailchimp**, **WordPress.com** — используют PHP.
  - Большинство крупных CMS — на PHP.

---

## 🧠 Что сказать студентам:

**PHP = быстрый старт + зрелая платформа + плохая репутация в прошлом.**  
Но сегодня он:
- Быстрый (JIT, OPcache),
- Стандартизированный (PSR),
- Организованный (Composer, MVC),
- Тестируемый (PHPUnit, Pest),

# Когда PHP — разумный выбор

---

## 🎯 Главная идея

> Если проект типовой, сроки ограничены, бюджет невелик, и нужна быстрая поддержка — **PHP отлично справляется**.

PHP — это не просто «старый язык», а зрелая, надёжная и до сих пор **широко используемая технология** для многих типов задач. Особенно когда речь идёт о **классическом вебе**.

---

## 🔹 Тип 1: Простые CRUD-приложения

CRUD — это аббревиатура:
- **C**reate (создание)
- **R**ead (чтение)
- **U**pdate (обновление)
- **D**elete (удаление)

### Примеры задач:
- Панель управления для товаров
- Учет заявок на ремонт
- Простой внутренний портал компании

### Почему PHP подходит:
- Быстрое развертывание на Laravel или Yii2.
- Есть готовые шаблоны, админ-панели (Backpack for Laravel, Laravel Nova).
- Быстрый REST API без лишнего сложного бэкэнда.
- Почти не требует DevOps-инфраструктуры.

🛠 **Инструменты:** Laravel + Eloquent ORM + Blade шаблоны.

---

## 🛒 Тип 2: Интернет-магазины

### Примеры платформ:
- **WooCommerce** — плагин для WordPress (PHP).
- **PrestaShop** — самостоятельная CMS для e-commerce.
- **OpenCart** — лёгкий движок для магазинов.
- **Magento (Adobe Commerce)** — мощная платформа, тоже на PHP.

### Почему PHP подходит:
- Тысячи готовых плагинов (оплаты, доставки, скидок, SEO).
- Простота интеграции с платёжными системами и 1С.
- Большое сообщество, готовые темы, модули.

🧑‍💻 **Часто не нужно ничего программировать** — сборка магазина из модулей.

---

## 🌐 Тип 3: Сайты на WordPress, Drupal

WordPress — **самая популярная CMS в мире**, работает на PHP.

### Примеры задач:
- Лендинги
- Блоги
- Корпоративные сайты
- Порталы, справочники

### Почему PHP подходит:
- Можно развёртывать за часы.
- Поддерживается миллионами хостингов.
- Интеграции с CRM, аналитикой, мессенджерами.
- Легко находить специалистов и темы.

📈 **WordPress занимает более 40% всех сайтов в интернете**.

---

## 🔄 Тип 4: Быстрые REST API и админки

PHP-фреймворки позволяют быстро поднимать API и админки:
- Laravel, Slim, Lumen, Symfony
- Поддержка OAuth2, JWT
- Маршрутизация, миграции, валидация из коробки

### Примеры задач:
- Мобильное приложение, которому нужен сервер
- Отдельный сервис с API для фронтенда на Vue/React
- Система управления пользователями, заказами, контентом

### Почему PHP подходит:
- Высокая скорость прототипирования.
- Широкая база пакетов (Guzzle, Spatie, Laravel Passport).
- Удобное логирование, тестирование, валидация, миграции.

---

## 📌 Когда PHP — НЕ лучший выбор?

- Сложные real-time системы с WebSocket (лучше Node.js, Go).
- Высоконагруженные стриминговые платформы (Java, Rust).
- ML, Big Data, анализ — Python, R, Julia.
- Мобильные бэкенды со сложной логикой и масштабированием — может потребоваться Go, Java.

Но… даже там **часто часть архитектуры остаётся на PHP**.

| Задача                               | PHP — подходит? | Почему                                               |
|-------------------------------------|------------------|-------------------------------------------------------|
| Блог, сайт, лендинг                  | ✅ Да             | WordPress, быстро, дешево                            |
| Интернет-магазин                     | ✅ Да             | WooCommerce, OpenCart, модули, хостинг               |
| CRUD-система, админка                | ✅ Да             | Laravel, быстрый старт, шаблоны                      |

| Стриминговая платформа               | ❌ Нет            | Нужны более низкоуровневые и эффективные языки       |
| Обработка больших массивов данных   | ❌ Нет            | Python, Spark, Hadoop эффективнее                    |
